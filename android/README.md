# 朝夕日历 · Z Fold6 / Windows 同步版

原生 Android 应用，使用 Android Views 与 Jetpack WindowManager。安装 APK 后即可使用；不需要苹果开发者会员或按周重新签名。

## 使用

1. 安装交付包中的 Android APK；保留安装包供以后更新。更新时直接覆盖安装，不要先卸载，以免删除尚未同步的本机修改。
2. Windows 运行包内的更新脚本。脚本先保存旧程序和日历备份，再更新电脑端，备份在个人目录的 `Daynote/Backups`。
3. 在 Windows 的“账号与同步”和手机右上角“设备”中输入同一份本人配对码。确认连接后，本机已有日程才会上传。配对码相当于密码，另外交付，不在 APK 或代码里。
4. 打开两端应用，先用一个虚构事项验证新增、修改和删除。手机和电脑不需要在同一个 Wi-Fi 下，均需能连接云端服务。

## 折叠屏与小组件

- 外屏或窄分屏：单栏月历和日程列表。
- 展开后的宽窗口：左侧月历、右侧事项。根据可用窗口宽度调整，不按手机型号硬编码。
- 识别折痕位置；折叠、旋转和切换窗口大小时保存所选日期、月份、筛选和编辑草稿。
- 手机“设备”中点击“添加桌面小组件”，或长按 One UI 桌面 → 小组件 → 朝夕。支持拖动调整大小，按可用空间显示 2、3 或 5 条近期事项。
- 小组件可打开事项、新建和刷新。内容来自本机缓存，未联网也能查看。仅用于桌面，锁屏宿主不显示日程内容。

## 同步与提醒

- 修改先原子保存到本机；联网后上传。前台打开时同步，编辑后同步，停留前台时每分钟检查。
- 后台注册约 15 分钟的联网任务，小组件的本地内容约每 30 分钟由系统请求刷新。Android 和三星省电策略可能延迟这些任务，不能承诺实时后台更新。需要马上更新时，打开应用并点同步。
- 两端同时修改时保留冲突副本；删除也带版本，避免离线设备把已删事项重新带回来。
- 每份本机资料绑定首次连接的账号，断开仍保留本地资料与账号归属，不能直接改连别人的日历。
- 需要提醒时在“设备”中开启通知并允许系统权限。全天事项以当天 09:00 减去提前量安排提醒；未安排日期、已完成和已删除事项不提醒。
- 本版使用系统普通闹钟，不申请精确闹钟权限；提醒时间也可能受省电影响。已拉到本机的提醒与云端是否在线分别处理。

## 资料与费用

日历、离线队列和有效备份保存在 Android 应用私有的不备份目录；配对码经 Android Keystore AES-GCM 加密保存。系统密钥暂时不可用时仍可离线编辑。

云端沿用现有项目，没有新开付费套餐；长期费用由服务额度和用量决定。云端按账号隔离，传输使用 HTTPS；这不是端到端加密。安装包不包含真实日程、配对码或应用签名私钥。

## 构建与验证

JDK 17、Android SDK 36、Gradle 8.13、AGP 8.13.2；最低 Android 8.0。可用 Android Studio 打开本目录，或执行：

```sh
./gradlew assembleDebug assembleRelease testDebugUnitTest lintRelease
```

Windows 也可运行项目根目录 `scripts/build-android.ps1`。本机 `local.properties`、签名配置和产物不提交。Release 使用维护者本地的固定签名密钥；没有签名配置时产物尚未签名，不能直接安装。Debug 使用独立的 `.qa` 应用标识，避免测试影响正式资料。

`DeviceIntegrationTest` 仅接受 `.qa` 调试包、私有测试配置及临时测试账号。按手机新增 → Windows 真正的同步客户端修改 → 手机拉取 → 手机删除 → Windows 确认的顺序验证。不要把个人配对码用于这些测试。

依赖：AndroidX Core / WindowManager 使用 Apache-2.0 许可，为折叠屏和 Java 回调提供支持；APK 不包含网页运行时。JUnit / AndroidX Test / JSON-java 仅用于测试。实际验证结果以交付包中的验证记录为准，不以编译成功代替真机验证。
