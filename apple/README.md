# 朝夕日历 · iPhone / Mac 原生预览版

这是 SwiftUI 原生应用，不是网页壳。与 Windows 互通版使用同一套个人同步码；你和朋友应各用一份同步码。同步码相当于密码，任何得到它的人都能读取和修改对应日历，请私下保存。

## 现在已提供的内容

- 直接打开的 `Daynote.xcodeproj`，一个目标同时支持 iOS 16 及以上、macOS 13 及以上。
- 中文月历、当天 / 全部 / 待安排 / 截止 / 已完成列表，日程编辑、颜色、完成与删除。
- 离线本机保存，前台每 30 秒、重新打开、编辑后和手动同步。
- 版本冲突保留副本、删除墓碑、不可变请求重试和账号隔离；同步码保存在系统钥匙串。
- 本机通知：根据已经获取的日程，安排最近的 60 条未来提醒。
- 本机原子保存、上一版 `.bak` 恢复和不含同步码的日程导出。

## 验证边界

本项目在 Windows 工作环境中编写并做过源码、协议、工程结构静态检查；该环境没有 Xcode，**尚未实际编译、运行或在 iPhone / Mac 真机验证**。提供的脚本会在你的 Mac 上先执行核心测试再编译。请保留构建错误，不要把未完成的构建当作可安装版本。

第一次使用前应在 Mac 跑完下面的构建与检查，再用虚构日程验证三端同步。不要把旧日历删除，或把云端当作唯一备份。

## 在 Mac 构建并使用

1. 从 Mac App Store 安装 Xcode，打开一次并完成首次组件安装；仅安装 Command Line Tools 不够。
2. 将完整 `apple` 文件夹复制到 Mac 本机文件夹中。
3. 双击 `构建Mac版.command`。脚本先运行 `swift test`，再构建本机签名的原生 `.app`，完成后在 Finder 显示它。
4. 将生成的“朝夕日历.app”拖到“应用程序”，打开后点右上角账号图标，粘贴自己的同步码。

若复制后的 `.command` 没有执行权限，可打开“终端”，输入 `bash `（后面一个空格），把脚本拖进终端后回车。不需要关闭 Gatekeeper，也不要运行网上的全局安全关闭命令。

也可以直接双击 `Daynote.xcodeproj`，在 Xcode 顶部选 `Daynote` 和 `My Mac` 后运行。

## 免费安装到自己的 iPhone

1. 双击 `打开iPhone工程.command`，或者直接打开 `Daynote.xcodeproj`。
2. Xcode → Settings → Accounts，登录自己的 Apple Account。无需把密码或验证码提供给其他人。
3. 选择工程里的 `Daynote` target → Signing & Capabilities；勾选自动签名，Team 选自己的 **Personal Team**。
4. 如果应用标识已被其他团队占用，在 Bundle Identifier 末尾添加自己的不含空格英文后缀，例如 `app.youmu.daynote.native.myname`。同一个人后续更新应保持这个标识，避免形成另一个应用。
5. 用数据线连接并信任 iPhone；按系统和 Xcode 提示开启 Developer Mode。顶部运行设备选自己的 iPhone，点击 ▶。
6. 在 iPhone 打开“朝夕日历”，粘贴与自己 Windows / Mac 相同的同步码。朋友使用自己的 Apple Account 和另一份同步码安装。

Apple 免费 Personal Team 的设备安装签名在签发 **7 天**后到期，需要从 Xcode 重新构建安装。重新安装更新时保持同一 Bundle Identifier，**不要先删除 App**，尤其存在未同步修改时。免费方式适合先测试，不能像 TestFlight 一样给朋友发一个永久有效的安装链接。规则见 [Apple 开发者账号说明](https://developer.apple.com/help/account/basics/about-your-developer-account/)。

## 第一次连接与日常使用

- 连接时会提示是否将本机已有日程加入云端。请核对同步码所属人；验证密钥前不会上传本机日程。
- 每份本机资料绑定首次连接的账号，断开同步会移除钥匙串中的同步码，但保留日程和账号归属。不能改用朋友的同步码混合同一本本机资料。
- 无网络时编辑照常保存在本机。重新联网并打开应用后点击“同步”，确认底部变为“已同步”。
- 两台设备同时改同一项时，云端版本保留，本机编辑以“冲突副本”另存。删除遇到更新冲突时保留云端新版本，并提示你重新决定。
- 有时间的日程按实际时刻同步并显示为设备当地时间；全天日程保留原日历日期。
- 系统通知需要用户允许。全天事项与 Windows 一致，以当天 09:00 为提醒基准，再减去所选的提前时间；“待安排”事项不触发提醒。
- iPhone 关闭应用后不会持续联网；在电脑新建或改时间后，需让 iPhone 打开应用获取更改，才能据此安排或取消本地提醒。此版未实现 APNs、后台即时同步、桌面小组件或共享日历。

## 本地数据与备份

Mac 沙盒资料通常在 `~/Library/Containers/<Bundle Identifier>/Data/Library/Application Support/DaynoteNative/`，实际路径受系统容器安排影响。iPhone 资料保存在应用私有容器。

`calendar.json` 保存日程、版本和离线队列，`.bak` 保存上一次有效写入。若主文件损坏会尝试备份，二者都无法读取时停止写入，不创建空文件覆盖。同步码只在钥匙串，备份和导出不包含同步码。

设置里的“导出日程备份”生成便于检查的 JSON。完整原位恢复应保留 `calendar.json` 与 `.bak`，在应用退出后恢复到原账号资料位置；此预览版尚未提供图形化导入按钮。

## 开发验证

Mac 上在本目录运行：

```sh
bash scripts/verify-apple.sh
```

它会执行 `swift test`，并分别编译 iOS 模拟器与 macOS 目标。未签名的模拟器产物不能装到真实 iPhone，真机仍需在 Xcode 选择 Personal Team。

测试覆盖：显式空日期、全天日期、断线重试保持相同 mutation、请求中编辑、双端冲突副本、删除传播及删除冲突、账号隔离、丢失响应后新版本合并、过期编辑窗口保护、长中文备注的字节分批、空云端不清空离线日程。

手动检查：用虚构事项在 Windows → iPhone → Mac 各编辑一次；将其中一台断网编辑后恢复；同时编辑同一项；删除后另一端不复活；输入另一人的同步码应被本机绑定保护拒绝；允许通知后创建几分钟后的提醒并锁屏观察。完成这些之前，不将真机通知和实际三端互通标为已验证。
